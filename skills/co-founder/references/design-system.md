# Premium design as a coherent system

These are original design recommendations, not claims that one visual recipe
improves every business. Start with the user's task, category, brand, and accepted
references. A reference is a principle to interpret, not a template to copy.

## Establish a visual thesis
Choose three defensible qualities, such as precise / calm / credible, or expressive /
editorial / warm. Say how each changes typography, layout, imagery, and interaction.
Keep product utility separate from marketing spectacle. Luxury photography is not
a reason to hide a business app's data. A technical brand need not look clinical.

## Typography
Use the existing approved family or a locally available system stack. Establish
roles for display, section title, body, label, caption, and numeric data. Begin with
few weights and consistent line heights; adjust by actual rendered text, not a
universal formula. Keep paragraphs readable and headings intentionally wrapped.
Use tabular numerals where aligned amounts matter. Test long titles, localization,
non-Latin glyphs, and zoom. Never distribute font files from the execution machine.

## Space and alignment
Set a modest spacing scale, consistent page gutters, content widths, and component
rhythm. Use whitespace to express grouping and hierarchy, not to conceal missing
content. Align related objects to a shared grid; avoid almost-aligned edges and
inconsistent radii. Mobile requires a new composition, not only smaller type.

## Color and material
Inherit brand colors. Define neutral surfaces, primary action, secondary content,
focus, and semantic states. Reserve accent for meaning. Avoid arbitrary colorful
cards, background orbs, glass everywhere, and gradients applied to every heading.
A purposeful bright or complex brand is valid: the test is coherence, not a ban on
color. Do not borrow an unrelated brand's palette because it is fashionable.

## Components and content
Use the same button, form, table, menu, dialog, badge, and empty-state logic across
routes. Distinguish primary/secondary/destructive actions. Keep common operations
visible. Build useful states, not only a pristine hero. Use accurate real assets,
credible proof, and clear copy; fabricated testimonials are not visual filler.
Photography/illustration should be owned or licensed and help the message.

## Interaction and access
Respect keyboard/focus behavior, accessible names, error recovery, and motion
preferences. For reference, WCAG 2.2 AA includes 4.5:1 minimum contrast for ordinary
text and 3:1 for large text (with defined exceptions), plus criteria for keyboard,
reflow, focus, and target sizing. A 44 CSS-pixel target is a useful project design
choice, not the universal WCAG 2.2 AA minimum. Verify precise applicability in the
[W3C quick reference](https://www.w3.org/WAI/WCAG22/quickref/).

## Performance and restraint
Reserve media dimensions; avoid unnecessary layout shifts and autoplay sound.
Give large images appropriate renditions. Do not add an animation framework to
fix a spacing issue. Hover effects should not move the target away. Keep essential
content available when animation/JavaScript fails where applicable.

## Acceptance
Render representative states at narrow, intermediate, and wide widths. Inspect
hierarchy, spacing, clipping, actual font availability, content stress, and actions.
Use human comparison with approved references. A numerical scorecard cannot prove
premium taste, brand fit, accessibility, or that something "does not look AI-made".
