# ui-polish — principles and review

**Core:** Function and brand before decoration; judge the rendered interface, not its source.

Product UI and marketing websites use different hierarchies and density.

Reuse actual components, tokens, assets and terminology; preserve the task and shared states.

Inspect realistic content, focus, errors, small screens and navigation; revise visible defects.

## Required review
- `hierarchy`: Task hierarchy, typography and density fit real content.
- `behavior`: Primary flow, states and responsive behavior are checked.
- `brand-fit`: Implementation matches the selected project surface.

Mark pass / revise / not-checked with an evidence pointer and a concrete reason.
Do not self-certify a result by repeating this checklist. Scope out a criterion
only with an explicit reason; required security or brand gates cannot be waived
by aesthetic preference. Use the shared quality-review record when handing off.
