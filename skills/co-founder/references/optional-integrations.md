# Optional integrations, not hidden requirements

Core workflows accept manually supplied sanitized context. Existing authorized
connectors can reduce repetition, but no connector is automatically installed.

| Need | Possible existing capability | Boundary |
|---|---|---|
| Browser QA | Host browser, Playwright, appropriate test environment | No real-customer screenshots; no false visual verification. |
| Support | Existing email/helpdesk connector | Read bounded cases; sending needs artifact/recipient approval. |
| Sales | Existing CRM/email/calendar connector | Use actual records; no fabricated access or bulk sends. |
| Growth data | Existing analytics/report export | Verify date range, filters, attribution; no inferred metrics. |
| Design assets | Approved local files or design connector | Preserve rights and originals; no copying other brands. |
| Video | Local studio, user's editor, optional Remotion | No mandatory paid service or undisclosed media API. |
| Daily brief | Supported host scheduler configured by user | Timezone, scope, availability, access, and approval required. |

Never extract subscription credentials to call unofficial APIs or run a hosted
service. Do not route other users through the founder's subscription. There is
no public endpoint, account broker, or autonomous backend in this package.

Scheduling documentation changes; consult current host docs at setup. Begin with
read-only briefs/drafts, not automatic publishing or customer communication. A
cadence written in a skill is not a created schedule, and an unavailable machine
cannot be assumed to run local work. Record actual scheduler confirmations.
