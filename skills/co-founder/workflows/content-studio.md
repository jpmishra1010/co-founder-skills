# Produce clean brand-specific posts and motion explainers

## Project binding and quality
Resolve the project using `references/project-identity.md`; bind this task to
its project ID, environment and, for visuals, the approved surface/brand bundle.
Read `references/principles/content-studio.md`. Apply its evidence-backed review
before handoff. Wrong-project context or an unapproved consequential action
is a blocker, not a missing detail to guess.

## Use and context
Use for product/personal-brand copy, posts, carousels, launch assets, or video.
Read only the relevant brand kit, audience, channel, approved message, source
assets, and verified claims. For static work read `references/social-craft.md`;
for video read `references/motion-craft.md` and `references/media-production.md`.
Read `references/craft-gates.md` and use its staged review. Read reference
research access statuses before claiming to have viewed anything.

## Procedure
1. Establish one audience, one useful message, one desired action, output format,
language, source assets, and what is allowed to change. Preserve exact logos,
product facts, names, and language requirements. Do not fabricate a customer's
story, founder experience, dashboard, analytics graph, testimonial, or result.
2. Resolve the post/video profile and exact registered assets before ideation.
For a new direction create and inspect a composition or styleframes first;
obtain approval for broad identity changes, or reuse an accepted direction.
Select a relevant content format: demonstration, problem/solution, practical
lesson, approved release, process explanation, or founder reflection. Choose
brand voice and category before layout. Do not copy a competitor's recognizable
identity or default to generic "AI" imagery and motivational clichés.
3. Static: write the short main message, supporting proof, and caption separately.
Create a coherent layout with meaningful whitespace and one visual hierarchy.
Adapt composition to each format rather than stretching/cropping blindly.
Use actual supplied assets or original illustration. No redistributing fonts.
4. Video: script → timed beats → storyboard → assets → animation → sound/captions
→ render → inspect. Use one primary idea per scene; make motion explain a state,
relationship, mechanism, or transition. Preserve object continuity. Avoid full
paragraphs on screen, constant zoom, arbitrary spins, and effect-driven pacing.
5. Choose tools to fit the approved concept, not a bundled layout. The v1 generic
box/diagram renderer is retained only for compatibility and smoke tests. The
source repository's `examples/connected-brand` project demonstrates a custom UI, campaign and
object-continuous motion; do NOT apply its fictional brand to other projects.
Use project-local HTML/vector/approved image tools or an existing video project.
If production capability is missing, deliver an explicitly unrendered draft.
6. Inspect actual exported assets at full resolution and realistic feed/phone
size. Check text fit, exact assets, contrast, hierarchy, crops, safe areas,
timing, first/last frames, audio sync/rights, and claim accuracy. Rework failed
areas; do not merely repeat a quality checklist. Human approval decides taste.
7. Deliver editable source/config, exports that actually exist, caption/script,
alt text/captions, asset provenance, checks, and gaps. All publishing remains
approval-gated. Reuse accepted formats without making every campaign identical.

## Deliverable / done
An actual artifact when tools permit, not just a prompt for a designer. Clearly
label drafts, silent samples, synthetic demonstrations, unverified claims, and
unrendered storyboards. No promise of virality, premium taste for all audiences,
or an objective "not AI-generated" certification.
